# 第二批：任务执行闭环

本批基于 `v2.3.0-rc.5`，对应 `TODO.md` 的五项执行闭环整改，不创建新版本、tag 或远端提交。改动前源码快照：`frontend-backup/20260906-pre-execution-loop-661acb1.zip`。

## 行为与入口

1. **复合资料**：附件是必需能力，不是互斥意图。保留 Router/Scheduler 选定计划，仅补齐缺失的视觉或文档分析；普通对话在任务入队前持久化本轮附件，运行时验证归属、大小与内容摘要。
2. **交付语义**：`completionEvidence` 版本 2 区分执行状态、人工接受、来源状态。`evidenceValidation` 根据当前任务的真实回执和 Artifact 归属重建校验信息，清除模型自报标记。人工接受和来源可追溯都不等同于事实已核验。日程接续与质量基线同步使用新语义。
3. **工具执行记录**：SQLite/PostgreSQL 为通用 Tool Registry 保存调用标识、租约、回执和人工核对记录。恢复使用原调用标识，明确的重跑使用新标识。租约过期的读取可有界重试，写入结果未知则停止重放。外部 MCP 保留内层审批记录，核对过程不能删除记录或更换审批来绕过保护。
4. **多轮工具循环**：Agent 从真实观察决定下一轮动作；`agent.tool_loop` 在副作用前保存决策，在获得回执后保存观察。默认最多 8 轮、24 个调用及内部 64,000 Token 预算，同时仍服从原有任务预算、工具配额、权限和超时。预算估算不冒充 Provider 精确 Token。
5. **长对话**：有原文引用的结构化约束与决定，支持模型选择的替换和撤销，拒绝跨消息或伪造来源；原文始终保留。`context.read` 只能读取当前任务所有者对应的会话或 Nexus 历史，不能指定任意用户。大段来源和提取故障保持部分覆盖状态。

在任务详情的工具执行记录中处理不确定结果：先核对外部系统，填写依据，选择确认已完成或确认未执行，再点击继续任务。确认已完成只记录人工核对，不能伪造工具回执；确认未执行也不能绕过其他待审批项目。任务恢复使用 revision 检查，旧页面不能静默覆盖新状态。

本批保持默认英文、可切换中文，保留现有布局和毛玻璃样式。新增恢复面板有双语文案、任务切换竞态保护、同步提交锁及窄屏操作入口。历史对话的延迟尺寸变化继续跟随底部，但用户主动上滚时不抢回位置。

历史保存只做确定性摘要与本地来源校验，不因保存操作额外调用云模型。语义提取发生在实际 Chat、任务或 Nexus 请求中，使用本轮选择并验证归属的模型；提取失败时保留降级状态，无效或不归属的凭据则拒绝请求，两者均不回退到默认云服务。直聊临时提取不异步覆盖较新的会话记录。

重复写操作不会在同一轮循环中再次派发，但读取、修改、再读取验证会获取新内容。连续两轮相同只读调用返回相同结果时停止无进展轮询。Provider 截断的 Agent 响应标记为部分结果，其中的工具请求不会被执行；恢复时工具定义或默认参数漂移导致的身份冲突也会停止该 Agent，不让模型换一个调用 ID 绕过去。

## 保留边界

- 任意第三方服务无法由平台单方面保证“恰好一次”。不支持幂等或无法确认响应的写入，仍需人工核对；平台保证不因未知结果盲目重发。
- 结构化约束由模型提取并核对原文出处。出处真实不意味着语义理解永远正确，原文可检索、部分覆盖明确保留，不承诺无限上下文。
- 原文检索沿用 Tool Registry 的执行开关（`AXIOM_TOOL_EXECUTOR=docker`）。内置通用推理步骤可使用已注册的 `context.read`；自定义 Agent 与 Agent Nexus 的显式工具权限保持不变，需要允许该工具。直聊、单 Agent 快答及视觉、文档、搜索等 specialist 快路径不进入通用工具循环，不承诺其可以主动调用原文检索。
- 多轮循环提供有界执行机制，不保证任何目标都可完成。无进展或超预算时留下部分结果与原因，不冒充成功交付。
- 真实 MCP OAuth、外部 MemoryCore/Harness、供应商凭据及目标部署性能仍需现场验收。第三批产品质量与真实任务成功率评测继续单独追踪。
