# 业务能力 V2

更新时间：2026-09-03

这组升级解决的不是“页面上多 15 个开关”，而是让复杂任务从理解需求、分工执行、证据核验，到交付后的复用和协作都能形成可恢复的闭环。所有状态都复用现有 Task、Event、SSE、Artifact、Agent Registry 和人工审核体系，没有另建一套演示数据。

## 一次复杂任务会发生什么

1. Router Agent 判断任务类型和难度，简单问题仍然直接回答。
2. Scheduler Agent 选择本轮需要的 Agent、Skill 和模型，并给出选择理由。
3. Planner 生成带输入、输出、证据和完成条件的执行计划。
4. Agent 按依赖关系并行工作，通过结构化交接把摘要、Artifact 和未决问题传给下游。
5. 失败、证据不足或人工补充要求时，Replanner 只重排受影响部分，保留仍有效的结果。
6. Reviewer 检查证据、引用、风险和验收条件；证据冲突时不能标记为已验证。
7. 交付后可以继续分析、局部重跑、换模型复核、导出、保存为 Nexus/插件、创建日程或发送通知。

## 15 项能力

### 1. 有边界的动态重新规划

Agent 失败、关键证据缺失或用户在执行中改变要求时，系统会生成新一代计划。事件中保留触发原因、新旧计划差异、保留和失效的步骤以及计划代次；不会因为一个步骤失败就无条件从头运行。重新规划导致风险或预算上升时，任务进入人工确认。

### 2. 结构化 Agent 交接

每个 Agent 步骤都有输入、输出、证据要求和完成条件。交接结果保存摘要、Artifact ID、证据 ID、未决问题和完成状态，下游 Agent 按契约消费，不需要从一大段自由文本中猜测上游做了什么。

### 3. Nexus 附件与 Artifact 传递

Agent Nexus 可以上传附件，也可以链接当前租户已有的 Artifact。连线支持四种传递方式：摘要、全文、指定字段和只传引用。发布及恢复时固定工作流版本和附件引用；服务端检查租户归属、MIME、大小和内容是否仍然可用。

### 4. 动态 MCP/OpenAPI 工具目录

项目空间可以导入 OpenAPI 3.x 或 HTTP MCP 服务。平台会发现或固定工具目录、校验参数 schema、限制允许使用的 Agent，并把启用的操作注册到主 Tool Registry。模型发起的原生工具调用仍经过 SSRF 防护、风险审批、调用配额、超时、审计事件和 Artifact lineage，不会从业务能力 API 绕过原有安全边界。

### 5. 证据图和引用质量门禁

任务结果可以记录用户事实、工具结果、外部来源和模型推断，包含来源、时间、定位信息、置信度和 Artifact。页面会区分已验证、来源支持、未验证和存在冲突；缺少关键证据或出现矛盾时，Reviewer 不能把结论当作已验证交付。

### 6. 项目空间

一个项目可以集中管理目标、验收条件、策略、成员、任务、会话、Nexus、日程、Artifact、评论、决策和审核。资源删除或生命周期清理后会自动解除项目引用。项目归档后所有写操作统一拒绝，重复归档保持幂等，并可导出完整项目记录。

### 7. 可控长期记忆

用户可以查看和管理记忆的来源、L0-L3 层级、作用域、置信度、过期时间和同步状态，也可以更新、停用或删除支持删除的层级。任务面板可以关闭本轮记忆使用。未配置 MemoryCore 时，本地策略记录仍可管理，但平台会明确显示降级，不会假装已经完成外部 L0-L3 写入。

### 8. Nexus 测试、版本与发布

Nexus 草稿可以保存测试用例并真实运行到任务终态。发布会固定当时的定义、版本和摘要签名；两个发布版本可以比较 Agent、步骤和连线变化，也能恢复为新的草稿。生产运行读取指定发布版本，不会跟随之后的草稿修改。已发布 Nexus 可以生成固定版本的 Workflow Plugin。

### 9. 交付后的下一步

任务面板会根据真实状态展示可用动作，包括继续分析、换模型复核、保存为 Nexus、保存为插件、局部重跑、导出报告、创建日程和发送通知。每次写操作带幂等键，重复点击不会生成多份相同资源。

### 10. Agent 级人工干预

运行中的单个 Agent 可以暂停、恢复、跳过、替换或锁定结果，页面同时显示受影响的下游、预计 Token 变化和风险变化。决定会写入任务事件；服务重启后仍可恢复，不依赖浏览器内存。

### 11. 多人协作与审核

项目支持负责人、编辑者、审核人和只读成员，并提供评论、提及、决策和审核分配。编辑使用 revision 防止多人静默覆盖。审核必须填写真实通过依据或修改意见；通知可定位到对应项目。租户之外不可访问，项目成员权限也由服务端再次校验。

### 12. 反馈进入评测闭环

交付后可以提交星级、问题类型、说明、证据纠错和修订答案。反馈会关联任务类型、路由版本、模型、Agent、角色和 Skill，进入统计与模型选择权重；不会只保存成一条无人使用的评论。

### 13. 十个可直接使用的解决方案

内置行业资讯、论文调研、GitHub 评估、竞品研究、需求分析、数据报告、营销素材、工作总结、文档审查和插件生成。每个方案都定义需要输入什么、会经过哪些步骤、如何验收以及最终交付什么。

### 14. 可解释的 Agent 和模型选择

自动选择会综合任务类型与角色适配、历史成功率、Reviewer 首次通过率、时延、Token、费用、重试、人工接管和用户反馈。页面显示候选模型及理由；用户显式指定模型时仍以用户选择为准。

### 15. 随真实事件修正的预估

运行前按同租户、同类型历史任务给出耗时区间、Token 区间、Agent 数量、成功率、预计人工确认和可信度。样本不足时明确标记冷启动，不伪造精确数字。运行中根据已经完成的步骤和真实事件修正剩余时间及进度，不使用固定倒计时动画。

## 数据与恢复

业务记录在 SQLite 和 PostgreSQL 使用同一份契约。SQLite 适合本地单人使用；PostgreSQL 支持多 Worker 共享状态、revision 并发冲突和跨进程资源解绑。PostgreSQL 首次初始化使用 advisory lock，避免多个 Worker 同时建表时触发系统目录唯一键竞态。

动态外部工具在服务启动时从持久记录恢复，并注册到与 Orchestrator、Task API 共用的 Tool Registry。项目、记忆、Nexus 发布、反馈和后续动作均按租户保存；归档、删除与 Artifact 清理会同步解除关联。

## 验收命令

```bash
npm run check
npm test
npm run build
npm run qa:visual
npm run qa:business-postgres
npm run qa:all
```

`qa:business-postgres` 只在设置 `AXIOM_TEST_DATABASE_URL` 时执行真实 PostgreSQL 验收。该地址必须指向允许测试清理的独立数据库，不能使用生产库。未配置时测试和生产门禁会明确显示 `skipped`，这不代表 PostgreSQL 已验收。

2026-09-03 最终验收使用本地 Docker PostgreSQL 15 的独立测试库完成：`npm test` 为 `373 passed / 0 failed / 0 skipped`，`npm run qa:all` 为 `25 passed / 0 failed / 4 skipped`。Nexus 回归会先真实运行测试、发布固定版本，再验证 Loop、历史恢复和会话隔离；发布测试任务不会进入用户的 Nexus 对话历史。4 个跳过项仍是未配置的 MemoryCore、外部对象存储与 Harness/Codex sidecar，不计作外部生产通过。

## 当前边界

完成这 15 项后，项目仍定位为本地或受控环境的生产候选，而不是可直接暴露到公网的完整企业 SaaS。MemoryCore、MinIO/S3/COS 和 Harness/Codex sidecar 没有配置时会使用本地能力或明确降级；真实多 Worker 容量、外部身份系统、Secret Manager、外部可观测平台、备份恢复和灾难演练仍需要在目标部署环境完成。
