# 受控 RSI：任务改进

## 这是什么

这是 Recursive Self-Improvement（递归自我改进）在 Axiom 的第一阶段：从已结束任务中复盘，提出下一次可以尝试的改进，再由用户决定是否试用。它不是模型训练，也不是可以自行修改平台的后台 Agent。

入口是左侧 **任务改进 / Task improvements**。来源选择展示当前用户最近 100 个终态任务。现有任务执行、Router/Scheduler、Agent Graph、Nexus、插件、记忆与人工审核保持原来的职责。

## 使用流程

1. 选择自己的一个已完成、失败或取消的任务，可补充希望改善的地方。
2. 点击生成。平台使用来源任务绑定的文本模型，分析有界的任务摘要、执行结果和该用户对此任务的反馈。界面立即显示处理中；这一步会产生模型调用费用。
3. 阅读复盘、改进建议和建议验证的场景。任务指标来自已有记录；模型的解释和建议不当成已核实事实。
4. 选择保存建议或忽略。**保存不代表上线，也不代表已经验证有效。**
5. 已保存建议可带入一个新对话的草稿；用户检查、补充材料后自行发送。有未发送文字或附件时，先确认已经保留原输入和附件，才允许替换。新任务仍由原有路由与执行系统处理，不修改原任务。
6. 后续任务结束后，可选用上一版建议作为参考再复盘，形成最多五代的人工控制迭代。父建议同样是参考数据，不是系统命令。

带入草稿只复制来源任务保存的需求文本，不额外恢复原会话、附件或 Nexus 的固定流程。需求文本超过 20,000 字符时会提示截断，发送前需核对补全。涉及文件请重新上传；若要优化 Nexus/插件，请通过它们原有的草稿、测试、发布和回退流程操作，不能把普通对话试用当成原流程已经升级。已忽略的建议可以重新保存，不必再次调用模型。

## 与现有业务的边界

| 机制 | 本次行为 |
| --- | --- |
| Router / Scheduler | 不增加第二个在线调度器，不改现有评分与路由权重 |
| 当前任务和 Agent Graph | 只读取终态任务，不中途重排、不重跑、不覆盖执行记录 |
| 工具与外部副作用 | 复盘模型不获得任何工具；不发送消息、不改文件、不搜索、不生成媒体 |
| 记忆 | 不写入长期记忆，不把模型建议自动升级成个人偏好或系统指令 |
| Nexus / 插件 | 不修改草稿、发布快照、固定版本或授权 |
| 质量审核 | 不修改验收规则或降低审核门槛；建议用例只是一份待执行计划 |
| 用户范围 | 来源、反馈、父建议、列表、详情、状态操作和试用草稿均按 tenant + user 所有者检查；管理员身份不在此入口获得他人的复盘内容 |

这不是全平台账户隔离已经完成的声明。单机未配置签名身份时仍沿用平台本地身份；公开多用户部署必须先完成可信登录与整个平台的访问隔离，不能信任浏览器自行发送的用户标识。

## 可靠性约定

- 记录保存在现有业务记录库，使用新的 `improvement-proposal` 类型，兼容 SQLite 和 PostgreSQL，无需新外部服务。
- 每次生成带幂等键；同一次请求重复到达不会并行重复调用模型，同键不同参数拒绝。
- 生成前持久化处理中记录，模型调用有超时和输出上限。失败显示为失败，不使用固定模板冒充模型复盘；超时遗留记录可在再次读取时识别。
- 保存/忽略操作检查 revision，旧页面操作冲突时需要刷新，不静默覆盖。
- 来源被删除或变得不可访问时，派生建议不再经此入口返回；来源执行改变后不能把旧复盘当成当前执行的有效建议。
- 不保留模型凭据、完整工具日志或附件内容；任务摘要有界并对常见凭据格式脱敏。脱敏不是完整 DLP，用户输入的其他个人资料仍可能传给来源任务所配置的模型服务。

## API

所有路径以 `/api/improvements` 开头：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /sources` | 当前用户可用于复盘的终态任务 |
| `GET /` | 当前用户可访问的建议 |
| `GET /:id` | 建议详情与状态 |
| `POST /` | 用户明确发起生成；`taskId`、`idempotencyKey`，可选关注点与父建议 |
| `PATCH /:id` | 使用 revision 保存或忽略建议，不发布任何执行策略 |
| `POST /:id/prepare` | 已保存建议转成新任务草稿，不执行任务 |

## 验证和后续阶段

`npm test` 覆盖后端状态、隔离、并发、错误和“不改变当前业务”的约束；`npm run qa:improvements` 覆盖真实前端组件的生成反馈、状态转换、草稿交接、中英文与移动端。浏览器专项使用隔离的 API 样例，不访问真实任务或付费模型。

目前所有建议的效果都是 **未验证**。结构检查、后端回归通过、用户点击保存或模型自评，都不能证明业务质量提高。

本批执行与测试记录见 [2026-09-19 验收](fixes/2026-09-19-controlled-rsi.md)。

后续阶段单独实施：

- 独立留出任务集上的基线/候选对照，记录完整性、事实与证据、成本和延迟，不能只重复优化过的同一道题。
- 对可执行流程使用隔离环境和模拟工具，避免评测重复触发真实外部操作。
- 评测通过的个人策略版本及明确授权的团队版本，小范围发布、停止开关和可回退历史。
- 在可信登录、私人空间、文件与工具隔离完成后，才考虑跨用户汇总或共享优化。
- 不在这一阶段加入核心代码自修改、数据库迁移、权限扩张、模型权重训练或无人控制的递归执行。
