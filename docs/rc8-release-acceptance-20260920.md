## 首轮发现与修复

首轮完整门禁为 39 passed / 2 failed / 3 skipped；视觉检查第一次失败、重试通过。保留 `qa/rc8-first-gate-results.json` 与原始日志，不将最终复验描述成首轮全通过。

1. **智能体目录回复冗长。** 真实模型问答在原 900 字符阈值附近波动；统一网关与任务入口的概览提示，按用途简要分组，详细技术清单请求仍可展开，不固定回答、不硬截断、不放宽原阈值。最终轮搜索专项已通过，目录回复 387 字符。
2. **英文 Readiness 漏翻译。** 补充独立文件工具、工作区写入说明及任意模型名的动态配置提示，并保护用户命名与模型标识。新增两项语言回归。
3. **视觉断言的阶段竞争。** 旧断言只认英文 `Agent`，误判合法中文角色“直接响应”。改为等待已路由请求，在固定 SSE 夹具保持待执行期间精确检查“直接响应正在准备执行”。
4. **测试依赖开发者环境。** Fake 搜索单测显式设置、恢复功能开关，补充“禁用时 0 次网络调用”；干净副本不再依赖本机搜索配置。
5. **复现脚本构建模式。** 测试环境的 `NODE_ENV=test` 会让 Vite 输出开发调试元数据；脚本的构建步骤改用 `production`，保留严格的 HTTP 路径泄露断言，未放宽产品 API 检查。
6. **旧审批夹具。** 补齐英文翻译后，语言测试继续到达了旧审批夹具：普通工具一次明确授权已应直接提交，旧夹具却期待第二次弹窗。移动端弹窗测试改为明确的 `critical` 工具，同时保留普通工具立即授权/拒绝的独立回归；测试自身返回的 400 不能误记为后端故障。
7. **性能失败的测试级联。** 第二轮无头桌面渲染 P95 分别为 66.7ms、50.1ms，超过原 50ms 门槛。失败后测试未清理全屏/面板，导致下一翻译测试超时；新增 `finally` 清理及明确的面板状态，不修改性能阈值或业务代码。第二轮完整记录为 39 passed / 2 failed / 3 skipped，保留 `qa/rc8-second-gate-results.json`；原始性能失败与修复后的独立复验分开记录，不用测试清理修复冒充渲染性能提升。

## 前序复验中的在线模型波动

第二轮完整门禁的 `qa:routing` 首次为 6/7，一次 `production-architecture` 调度引用了 `tradeoffs`、`risk-analysis`：它们是 Agent 的能力标签，不是已注册 Skill ID。服务端目录校验拒绝该计划并安全降级为研究员 → 分析员，保留完整输入与合法 Skill；没有执行不存在的 Skill。日志中的模型请求 `completed` 仅表示收到响应，不等于计划校验通过。

当轮整组重试后为 7/7、无降级，保留两次结果；第三轮完整门禁中的在线路由首次 7/7。不能将最终通过描述为全过程首次全通过。137 项确定性路由故障回归与在线路由评测分开计算，也不冒充架构任务已完整执行或交付已通过事实核验。后续仍需加强 Scheduler 对能力标签和 Skill ID 的区分及固定回归，这是候选版的已知可靠性边界。
