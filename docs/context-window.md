# 上下文窗口策略

## 当前策略

会话历史与模型上下文是两条不同的边界：

- 会话历史保留完整消息，供用户回看、恢复和审计。
- 模型请求使用有界上下文。超过 16 条消息、48K 字符或 `AXIOM_CONTEXT_MAX_TOKENS`（默认 12K）后，保留最近 12 条原文，把更早消息压缩为 `历史上下文摘要`。
- 长会话摘要会持久化到 SQLite/PostgreSQL 的会话记录中，但不会覆盖或删除任何用户原文，也不会改变 Agent Graph。模型请求只使用“已验证摘要 + 最近原文”的有界副本。
- 重复的早期消息会去重；过长消息按首尾保留；图片和文件只记录附件数量，不把二进制内容写入摘要。
- 最新一条用户消息始终保留。上下文仍然超限时，优先保留最新消息，再从较早的近期消息向前收缩。
- 默认使用保守的中英文混合 Token 估算 `axiom-estimate-v2`；部署可以在请求组装层注入 Provider 的精确 tokenizer，但只有真实实现才允许标记为 `exact`。返回的窗口元数据包含 `summaryVersion`、覆盖范围和 Token 数，便于回归和容量观测。

## 持久摘要与校验

持久摘要使用 `deterministic-incremental-v1`，记录 `summaryId`、单调版本、覆盖消息 ID、覆盖起止位置、来源 SHA-256 digest 和生成时间。新消息追加后只合并新进入覆盖范围的旧消息；如果任何已覆盖消息内容发生变化，digest 校验会失败，旧摘要不会继续进入模型请求，系统会从当前原文重建下一版本。

摘要还索引与当前会话相关的 Artifact、审批事件、人工补充要求、Agent 冲突、审查缺口和未完成任务。浏览器刷新或服务重启后，`/api/chat` 只有在消息 ID 与来源 digest 都匹配时才恢复该摘要；否则退回到当前请求的确定性窗口压缩。

在线回归 `npm run qa:context-summary` 验证首次生成、API 恢复、增量升版、来源漂移重建和原始消息保留；TaskStore 集成测试另外验证 SQLite 关闭并重新初始化后的恢复。

每个摘要还持久化 `quality`：记录本次是创建、直接复用、增量更新还是来源漂移重建，以及覆盖消息数、原始/摘要字符和 Token、压缩比例、覆盖比例、复用和重建计数、tokenizer 名称与可信模式。`GET /api/runtime/operations` 只按当前租户用户聚合这些数字，不读取或返回对话正文；运行观测页面据此显示长对话整理效果。短摘要可能只完成结构整理而没有节省 Token，此时如实显示 `0%`，不会强行美化压缩率。

普通对话由服务端执行压缩，主页工作流和 Agent Nexus 在构造工作流输入时执行同样的窗口策略。三处阈值保持一致，避免“对话能看见但 Agent 看不见”的漂移。

## 任务语义

- 普通对话每轮重新进行语义路由；同一话题的追问由模型看到摘要和最近原文。
- 动态工作流在任务类型不变时复用当前 Graph；任务类型改变时由 Planner 重新规划。
- 用户手动编排的 Agent Nexus 固定画布，不会因普通追问自动改图；追问只作为该 Nexus 的新输入。

## 后续演进

1. 为已知 Provider 接入精确 tokenizer，替换默认保守估算，并保留估算结果用于故障回退。
2. 建立摘要前后任务正确率和关键事实保持率评测；当前已观测压缩、覆盖、复用和重建，但这些运行指标不等于语义质量。
3. 对特别长的结构化附件增加分块摘要和引用级回读，避免把整份文档重新放回对话上下文。
