# 业务交付与稳定性收口

日期：2026-09-21。版本保持 `2.3.0-rc.8`，本轮内容进入 Unreleased，不改写已发布标签。个人空间、可信登录和自动 RSI 策略部署不在本轮范围内。

## 收口目标

不把路由正确、模型自评或任务终态当成业务质量。分别检查用户要求是否被保留、实际成果是否符合给定资料、结果是否可取回、故障后是否可恢复，以及副作用是否会重复。所有结果区分本地替身、真实模型小样本和外部部署现场验收。

修改前快照：`frontend-backup/20260921-pre-business-delivery-closure.zip`。本轮没有发布、推送或重启日常服务；日常运行实例需要另行重启才能加载后端修复。

## 实现

### 真实执行组件的确定性交付验收

`npm run qa:business-delivery` 包含 24 个案例，每域 4 个。调用真实组件，模型使用本地确定性替身，不接外网、不计算虚构 Token 或费用。

| 领域 | 业务判据 |
| --- | --- |
| 来源报告 | 真实 Markdown/Word/PDF 导出内容与来源配对；错误引用由独立判定器拒绝 |
| 文档分析 | Markdown 最新预算、Word 要求、PDF 页码与覆盖、损坏文档不伪造结果 |
| HTML/SVG 成果 | ToolRegistry、对象文件、目录和执行回执一致；恢复不重复写，不覆盖工作区；未知写入结果禁止自动重发 |
| 插件版本 | 发布重开、修改回草稿、回滚保留历史、删除后不复活 |
| Nexus | 真实图编译、条件 true/false、三轮 Loop、双输入汇合与上下游传递 |
| 对话恢复 | 最新需求经过重试保留、人工要求消费一次、取消停止下游、存储重开不重跑已完成步骤 |

这不是自动事实核查功能，也不证明插件游戏交互、截图美观、通用 SVG 安全或任意复杂任务准确率。SQLite 重开不冒充 OS 强杀；后者由 PostgreSQL 接管专项承担。

### Router 轻量路径

仅在首轮、无附件/历史/Graph、消息不超过 1000 字符时，Router 原始输出未经纠错且确认 `conversation`、`trivial`、置信度至少 0.95、只有 `direct-responder` 和 conversation 能力、无 Skill/外部事实/导出，才省略 Scheduler。仍执行同一调度结果校验。其余请求不变。

诊断新增 `schedulingPath`、`schedulerSkippedReason` 与真实省略事件。测试里的 `forceScheduler` 只用于受控对照，不是 HTTP 用户参数。减少一次模型调用不等于保证响应时间减半，也不减少执行、工具权限和审核边界。

### 持续质量门禁

`npm run qa:ci` 在临时源码副本运行，不复制 `.env`、数据库或历史产物；子进程只继承系统环境白名单。包括检查、全单测、生产构建、路由、交付、Fake MCP、RSI 和预览浏览器专项。新增 GitHub Actions Ubuntu/Windows 配置；本轮仅本地 Windows 实测，不能预称托管矩阵通过。

完整门禁逐次保留日志。失败后再次成功为 `unstable`，仍非零退出；`firstPassPassed`、`retried`、`flaky` 不被最后一次成功覆盖。在线路由每例每轮只请求一次，三轮为独立观察，不是替换失败的重试。

### 显式真实模型小样本

`npm run qa:business-live` 必须显式启用，使用用户配置的文本模型，可能产生费用。四例为给定来源比较、DOCX 预算、多轮约束变更、静态 SVG。最多 40 次供应商请求、每例 10 次、每次输出 1800 Token，整套 480 秒，无整套自动重试。原文、首次交付、实测用量、时间、路由与失败阶段保存到按时间归档的报告。

独立判定器精确检查源数据和约束，不调用模型给自己评分。SVG 只在离线 DOMParser 中检查固定静态子集，永不挂载执行，不代表视觉可读性。文档按 Router 选择适配成持久单步，运行真正的 document-agent 和不可变附件；不是完整上传 HTTP 网关测试。未覆盖实时搜索、图片/视频供应商、插件模型编程或所有 Nexus 场景。

## 发现的问题及处理

### 平台中断恢复缺陷

首轮 24 例中，第二个 Agent 执行期间的服务中断把未完成步骤写成了 `failed`，重开后被视为已经处理，无法继续。`orchestrator.ts` 现保留已完成步骤及并行兄弟结果，被打断的步骤留待恢复；超时仍走错误处理，未知工具副作用仍优先等待人工核对。增加真实 SQLite 关闭、重开及新 Orchestrator 回归。

首轮 `21/24` 另两项是新夹具解析错误：data URL 的 MIME 附带 charset、Word 文本提取未包含超链接目标。修正夹具后用真实 Word HTML 转换核对链接，没有降低业务期望。

### 新评测脚本的隔离缺陷

首轮真实模型 `3/4`。Word 路由失败时，测试目录缺少必要文档 Agent；原诊断未保存异常细节，不能把这一失败断言成线上路由缺陷。现补齐附件及专用 Agent，保存受控错误阶段和代码。

首轮脚本加载日常配置后创建 Task API，默认 Artifact Store 写出三份合成成果，默认 PostgreSQL Scheduler 打开连接使进程未退出。这是新测试器缺陷，不是用户历史被删除。已停止该测试进程；只读核对八条日程未发现本次窗口触发记录，日常服务 `/health` 为 200。没有事前快照，不声称数据库字节级零变化。

三份文件按报告 taskId 和文件名逐一核对后，整体移入 `frontend-backup/20260921-live-delivery-test-spill/`，可恢复，没有删除用户产物。新脚本从单独配置对象只取所需文本模型，清空部署环境，切换临时工作目录，显式传入 Artifact/Memory 依赖。新增带毒化 PostgreSQL、存储、记忆配置的独立进程测试，验证没有连接、没有写出和正常退出。`fetch` 约束只是模型网络边界，不称为进程级网络沙箱。

还修正了续写变量拼写、报告布尔值被数量覆盖，以及非法模型 URL 在清理逻辑之外留下空目录的问题。SVG 判定器加入命名空间及属性白名单，拒绝样式表、动画、隐藏、外来 iframe、覆盖成果的背景和画布外变换；文字重叠及对比度不属于该结构判定器的验收范围。所有失败和更正后的报告分别保留，不将过程描述为一次通过。

三项外部跳过为 MemoryCore HTTP、MemoryCore Axiom 适配器及 Harness/Codex sidecar。MinIO 为本地实测，不能代替目标云存储验收。业务评测脚本的环境清理/内存依赖补丁在全量阶段之后单独 24/24，并纳入最新完整离线 CI，核心 Runtime 代码在全量门禁期间没有变更。

## 仍需独立推进

- 正式 MemoryCore、Harness/Codex sidecar、目标对象存储和真实 OAuth/通知接收端的现场验收。
- 更大且领域匹配的留出业务集、跨模型和多次独立观测；真实来源核验与人工接受率。
- 多 Worker 大数据量下的长时故障演练、容量及成本指标；不把本机延迟当公网 SLA。
- 可信登录、私人文件和代码项目隔离仍按用户要求后移；当前不是公开多用户 SaaS 上线声明。
